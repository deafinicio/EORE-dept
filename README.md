# Твоя участь має значення · EORE dept

Інтерактивна презентація для знайомства молоді з відділом протимінної діяльності Харківської обласної організації Товариства Червоного Хреста України та можливостями волонтерства.

Оформлення та принцип взаємодії адаптовано з [department-year-2026](https://github.com/deafinicio/department-year-2026), референс `88d23182bbfc515dbeb2c2ba4c4e3226d34fe97a`: темна 3D-платформа, неонове підсвічування, локальний Rubik, поступова поява об’єктів, рух камери, каталог історій, вікна деталей і кінематографічні епізоди. Код сцени адаптовано під шість тем волонтерської презентації. Річні показники, персональні профілі й заплановану студію з річної презентації сюди не переносили.

## Вісім основних кроків

1. Знайомство з відділом.
2. Що ми робимо: інформація про ризики та безпечну поведінку.
3. Твоя можлива роль: вибір близького інтересу.
4. Твій досвід: можливості застосувати й розвивати вміння.
5. Mine Risk Map: опис і жива демонстрація.
6. Air Threat Map: опис і жива демонстрація.
7. Як починається участь: чотири кроки.
8. Запрошення познайомитися після виступу.

На платформі поступово з’являються шість об’єктів. Натискання на геометрію або її HTML-підпис відкриває історію. Ті самі історії доступні кнопками й через каталог. Короткий вступ має чотири кінематографічні епізоди, фінал - два. Це режими показу тих самих матеріалів, а не додаткові основні кроки.

Зміст поки адаптовано з попередньої презентації для волонтерів і винесено у `story.js` для наступного редагування. Конкретні завдання й необхідну підготовку команда погоджує індивідуально. Наведені ролі - приклади можливого внеску.

## Запуск

Статичний застосунок без збірки та backend. Через ES modules потрібен HTTP-сервер, а не подвійне натискання на `index.html`:

```bash
python3 -m http.server 8080
```

Відкрийте http://localhost:8080 . Презентація також працює на GitHub Pages. Three.js, шрифт, фото та всі інші ресурси локальні. Основні історії працюють з локального сервера без інтернету. Живі мапи потребують інтернету та доступності власних джерел даних. Без WebGL 2 доступні всі тексти, історії, вибір ролей і запрошення через HTML-кнопки; 3D та кінематографічний режим не запускаються.

## GitHub Pages

У **Settings → Pages → Build and deployment → Source** виберіть **GitHub Actions**. Після цього відкрийте **Actions → Deploy presentation → Run workflow**.

Очікувана адреса після успішної публікації: https://deafinicio.github.io/EORE-dept/ . Поки Pages вимкнено, workflow виконує перевірки та готує артефакт, а публікацію пропускає. Наступні зміни `main` перевіряються й розгортаються автоматично, якщо Pages увімкнено.

## Керування

| Дія | Клавіша / елемент |
| --- | --- |
| Наступна дія послідовного показу | →, Page Down, пробіл, кнопка справа внизу |
| Попередня основна сцена | ←, Page Up |
| Довільна основна сцена | Нижня шкала кроків |
| Перший / останній крок | Home / End |
| Відкрити поточну історію | Enter, коли фокус на заголовку або вільному місці |
| Каталог історій | O або «Каталог історій» |
| Режим виступу, приховати допоміжні панелі | P або ▣ |
| Повний екран | F або кнопка, якщо браузер підтримує |
| Нотатки доповідача | N |
| Довідка | ? |
| Закрити історію чи епізод, вийти з режиму виступу | Esc |
| Телефон | Горизонтальний свайп по вільному місцю сцени |

В епізодах стрілки перемикають ракурси; кнопка «Відтворити» запускає автоматичну послідовність і зупиняється на останньому епізоді. Основний автопоказ переходить між кроками з інтервалом 9 секунд і зупиняється на фіналі, при взаємодії або приховуванні вкладки. Системне зменшення руху й кнопка ≈ вимикають рух камери, появу елементів та автоматичний показ. Ручні переходи залишаються доступними.

Нотатки N відкриваються на тому самому екрані, тому аудиторія також їх бачить. Режим виступу не створює окремого приватного екрана доповідача.

Друк браузером створює вісім сторінок із текстом усіх тем, наявними фото й поточним обраним інтересом у фіналі. Це окрема читабельна версія для друку, без знімка WebGL-полотна.

## Контакт і дані

Наразі фінал запрошує підійти до команди після виступу. «Почати розмову» показує приклад звернення з обраним інтересом і дозволяє його скопіювати. **Заявка не надсилається.** Немає вигаданого контакту чи QR-коду.

Щоб додати погоджену форму або офіційний контакт, у `site.config.js` заповніть `contactUrl` реальним HTTPS-посиланням і `contactLabel` текстом кнопки. Порожнє, некоректне посилання або інший протокол приховуються. Не додавайте адресу-приклад як справжній контакт.

Обраний інтерес живе лише в пам’яті сторінки й скидається після перезавантаження. Застосунок не збирає персональних даних і не містить аналітичних трекерів. Зовнішній контакт, якщо його додати, має власні правила обробки даних.

Із референсу локально перенесено Three.js 0.180.0, FontLoader, TextGeometry, шрифт для 3D-напису EORE та Rubik із кирилицею. Ліцензії збережено у `vendor/LICENSE-three.txt` та `vendor/LICENSE-Rubik.txt`. Нових зовнішніх API, сервісів чи ключів немає.

## Перевірки

```bash
npm ci
npx playwright install --with-deps chromium
npm test
```

Тринадцять браузерних сценаріїв перевіряють реальний WebGL 2 через програмний GPU, вісім кроків, raycasting і HTML-маркери, навігацію й історію, вибір ролі, інтерактивні історії, кінематографічні епізоди, ізоляцію фокусу, режим виступу, керування рухом, мобільне компонування й свайп, роботу без WebGL, перевірку контакту та друк восьми сторінок. Програмний GPU дозволяє перевірити сцену в CI, але не замінює перевірку швидкодії й читабельності на реальному проєкторі.

У GitHub Actions ці самі тести використовують Chrome з [офіційного образу Ubuntu](https://github.com/actions/runner-images/blob/main/images/ubuntu/Ubuntu2404-Readme.md) через `PLAYWRIGHT_CHROMIUM_CHANNEL=chrome`. Окреме завантаження браузера та системних пакетів для CI не потрібне. Локально за замовчуванням використовується Chromium із Playwright.


## Послідовний показ і клікер

Одна кнопка `guided-next` переміщується між правим нижнім кутом сцени та нижнім правим кутом відкритої історії (native dialog top layer). Напис завжди показує наступну дію. Послідовність: додати об’єкт → відкрити історію на першому елементі → всі фото першої вкладки → наступні вкладки та їхні фото → закрити історію → додати наступний об’єкт. На фіналі кнопка відкриває запрошення, закриває його і пропонує почати спочатку. Довільне перемикання вкладок/фото оновлює поточну позицію послідовності. Кожне нове відкриття будь-якої історії починається з першого елемента, незалежно від попереднього перегляду чи вибраного 3D-підоб’єкта. Обраний інтерес для запрошення зберігається окремо.

Клікер працює як клавіатура. `PageDown`, `ArrowRight` і `Space` викликають ту саму дію; утримування клавіші (`event.repeat`) ігнорується; стрілки й пробіл у полях введення не запускають переходи. Page Down залишається командою показу навіть після роботи з фільтрами мапи. Довідка та кінематографічні епізоди мають власне керування. Презентація повинна бути активною вкладкою браузера. Моделі з іншими сигналами можна переналаштувати у програмі виробника на Page Down.

## Живі мапи

Використано чинні застосунки, а не копії або імітації даних:

- https://deafinicio.github.io/mine-risk-map/ — мапа інформаційних сесій, картки, фільтри й тепловий шар; опис за README оригінального репозиторію.
- https://deafinicio.github.io/air-threat-map/ — візуалізація відкритих повідомлень про повітряні загрози та індикатор тривоги для Харкова/Харківської громади; опис і межі застосування за README оригінального репозиторію.

Кожна мапа має окрему сцену, вкладку опису і вкладку повного живого інтерфейсу. Iframe завантажується при відкритті другої вкладки; його видалення після закриття історії припиняє роботу вкладеної мапи. Поновлення та доступність даних контролюють оригінальні застосунки. Повідомлення «Інтерфейс завантажено» не означає, що API повернув свіжі дані: статус видно всередині самої мапи. Є оновлення, посилання на окрему вкладку та кнопка повернення фокусу до показу. Автоматичних записів чи надсилання форм презентація не виконує.

На опублікованому Pages обидві мапи мають спільний origin із презентацією; обробник клавіш клікера під’єднується також усередині iframe. Під час локального запуску браузер ізолює інший origin: після взаємодії з мапою натисніть «До кнопки показу» або поверніть фокус у презентацію. Окрема вкладка також потребує ручного повернення до презентації. Мапи не підміняють офіційні повідомлення про безпеку; актуальні обмеження є в самих застосунках.

CI перевіряє вбудовування, інтерактивність і пересилання клавіш на контрольованій HTML-відповіді, щоб недоступність стороннього API не ламала перевірку презентації. Поточні live endpoints перевіряються окремо; зовнішні джерела даних і швидкість інтернету не контролюються цим репозиторієм.


## Оновлення оформлення 1.4

- Об’ємні літери EORE мають окремі кольори й проміжки; підкреслення та підставку під написом прибрано.
- Периметр 3D-платформи обмежено біло-червоною стрічкою на шести кілочках: чотири кути й середини довгих сторін. Шість безперервних прольотів мають плавне статичне провисання, тонкі кріплення й м’яку неонову ауру. UV-координати зберігають фізичний розмір діагональних смуг на різних за довжиною прольотах. Стрічка є декором і не перехоплює натискання на об’єкти.
- У «Твоїй ролі» видалено нижню смугу з мініатюрою. Права картка містить текст і відповідне зображення в спільній рамці; кадри вміщуються повністю. Студійний кадр позначено як візуалізацію.
- «Особистий розвиток» стоїть безпосередньо перед «Подорожами»: власні цілі, навчання, нові завдання й підтримка команди. Текст не обіцяє нагород, посад або кар’єрного зростання.
- Усі нові зображення проходять через спільну галерею та послідовний показ. Порядок ролей збережено, фото змінюється разом із роллю; новий блок розвитку автоматично включено в маршрут клікера. Жартівливу картку визначає метадані `joke`, а не фіксований номер вкладки.
